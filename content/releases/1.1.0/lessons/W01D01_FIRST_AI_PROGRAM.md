## Mission

מתיקייה ריקה לתוכנית Python שמקבלת שאלה, שולחת אותה למודל ומדפיסה תשובה. בסוף היום תוכל להסביר מי מריץ את הקוד, לאן נשלחת הבקשה, ואיפה נשמר המפתח. המטרה היא להבין ולבנות; אין צורך למלא ארבע שעות אם כבר הצלחת.

צריך Python 3, עורך טקסט וטרמינל. המערכת הלימודית עובדת ללא מפתח, אך התרגיל הזה שולח בקשה אמיתית ולכן דורש מפתח API ותקציב בחשבון שלך. אין כאן הרצת קוד או חיוב אוטומטי דרך האתר.

## Build First

פתח טרמינל. תיקייה היא המקום לקובצי הפרויקט; כל פקודה רצה מתוך התיקייה הנוכחית. ב־macOS או Linux:

```bash
mkdir first-ai-program
cd first-ai-program
python3 -m venv .venv
source .venv/bin/activate
python -m pip install openai
```

ב־Windows PowerShell השתמש ב־`py -m venv .venv` ואז ` .venv\Scripts\Activate.ps1`. אם הפעלת הסביבה חסומה, אפשר להריץ ישירות ` .venv\Scripts\python.exe` במקום `python`, בלי לשנות מדיניות אבטחה.

סביבה וירטואלית מפרידה את החבילות של הפרויקט מחבילות אחרות. צור קובץ בשם `.gitignore` לפני שמירת סודות:

```text
.venv/
.env
__pycache__/
```

צור מפתח דרך חשבון ה־API שלך, והגדר `OPENAI_API_KEY` כמשתנה סביבה מקומי. אל תדביק אותו בקוד, בצילום מסך או באתר הלמידה. אפשר לקרוא אותו בטרמינל בלי לכתוב את ערכו בהיסטוריית הפקודות. ב־zsh שב־macOS:

```bash
read -s 'OPENAI_API_KEY?API key: '
export OPENAI_API_KEY
printf '\n'
read 'AI_MODEL?Model ID from your account: '
export AI_MODEL
```

הדוגמה הזו מיועדת ל־zsh. במערכת אחרת השתמש בהוראות משתני הסביבה בתיעוד הרשמי. בחר מזהה מודל שנתמך בחשבון שלך; איננו מניחים שלכל חשבון זמינים אותם מודלים. הגדר תקציב קטן בחשבון לפני הניסוי.

צור `app.py`. ה־SDK קורא את המפתח ממשתנה הסביבה; הקוד קורא במפורש את שם המודל:

```python
import os
from openai import OpenAI

question = input("Question: ").strip()
if not question:
    raise SystemExit("Please enter a question.")

client = OpenAI(timeout=30.0, max_retries=0)
result = client.responses.create(
    model=os.environ["AI_MODEL"],
    input=question,
)
print(result.output_text)
```

הרץ `python app.py` ושאל שאלה קצרה. תשובה שחוזרת היא הוכחה שהחיבור עובד, לא הוכחה שהתשובה נכונה. שמור את גרסת החבילות שבה השתמשת:

```bash
python -m pip freeze > requirements.txt
git init
git add app.py requirements.txt .gitignore
git status
git commit -m "Build first AI program"
```

בדוק ב־`git status` שהקבצים הנכונים בלבד נבחרו. אם Git מבקש שם ודוא״ל, הגדר אותם לפרויקט לפי הוראות ההתקנה של Git. אין צורך לפרסם את המאגר ברשת.

## Concepts

**Python** מריץ את ההוראות במחשב שלך. **חבילה** מספקת קוד של אחרים. **SDK** הוא חבילה שעוטפת את ממשק השירות. **API** הוא חוזה של בקשות ותשובות. **HTTP** מעביר את הבקשה לשירות מרוחק. **מודל** מייצר את הפלט בצד השירות; הוא אינו הקובץ `app.py`.

`input()` קורא טקסט מהמשתמש. משתנה שומר ערך. `os.environ` מאפשר לקרוא הגדרות של התהליך. `print()` מציג פלט. Git שומר גרסאות של קבצים שבחרת לעקוב אחריהם; הוא אינו מנהל סודות.

זוהי אפליקציית AI עם קריאה אחת. אין בה בחירת כלים או לולאת החלטות, ולכן אין צורך לקרוא לה סוכן. קודם לומדים את המנגנון, אחר כך מוסיפים אחריות.

## Mental Model

```text
Terminal → Python app → SDK → HTTPS request → Model service
Terminal ← print()    ← SDK ← HTTPS response ← Model service
```

הפרד בין שלושה מקומות: קובצי הקוד בדיסק, משתני הסביבה של התהליך, והשירות המרוחק. המפתח מאפשר לשירות לזהות את החשבון; הוא לא הופך את המחשב שלך למודל.

## Deep Dive

נסה להסביר למה `python -m pip` מתקין חבילות עבור מפרש ה־Python שבחרת. הרץ `python -c "import sys; print(sys.executable)"` לפני ואחרי הפעלת הסביבה הווירטואלית ובדוק את ההבדל.

השהיה כוללת זמן רשת ועבודת השירות. ביטול בקשה מקומית לא מבטיח ביטול החישוב המרוחק. קבענו timeout והשבתנו ניסיונות חוזרים כדי שבניסוי הראשון יהיה קל יותר להבין כמה בקשות ניסית לשלוח.

## Failure Lab

בצע כל ניסוי בנפרד ושמור את ההודעה בלי סודות:

1. פתח טרמינל חדש בלי להגדיר `AI_MODEL`. מה נכשל, והאם הבקשה כבר נשלחה?
2. הזן שאלה ריקה. ודא שהתוכנית עוצרת לפני יצירת הלקוח.
3. הגדר מזהה מודל שלא קיים. הפרד שגיאת שירות משגיאת Python מקומית.
4. הרץ את התוכנית מחוץ לסביבה הווירטואלית. אם החבילה חסרה, בדוק את נתיב המפרש במקום להתקין שוב באופן עיוור.

עבור כל כשל: כתוב מה ציפית, מה קרה, הראיה שמצאת, ותיקון מינימלי. שחזר את ההגדרה התקינה והריץ שוב. אל תנסה ליצור שגיאות באמצעות פרסום מפתח או העמסת השירות.

## Challenge

הוסף אפשרות לשאול שאלה נוספת עד שהמשתמש מקליד `exit`. דחה קלט ריק בלי לשלוח בקשה. תכנן קודם על נייר אילו צעדים חוזרים ומתי עוצרים. אם עדיין אינך מכיר לולאות, נסה לקרוא את הפרק הרלוונטי במדריך Python; יום 2 יעמיק בנושא.

אל תוסיף מסגרת סוכנים למשימה הזו. הסבר למה ההחלטה להפסיק היא כלל תוכנה רגיל ואינה צריכה מודל.

## Mastery Check

סגור את הדוגמה ופתח תיקייה חדשה. שחזר סביבה, התקנה, קובץ תוכנית והגדרות בעזרת התיעוד בלבד. הצג:

- הרצה מוצלחת עם שאלה שבחרת ותיאור מסלול הבקשה.
- כשל מקומי אחד וכשל שירות אחד, עם דרך אבחון ותיקון.
- הסבר למה המפתח אינו נמצא במאגר ולמה תשובת מודל אינה בהכרח עובדה.
- הסבר ההבדל בין האפליקציה, ה־SDK והמודל.

שמור את הקוד ואת ההסבר כראיות. סימון הבנייה באתר מתעד את התרגול בלבד. אפשר להגיש ראיות במחוון שמתחת לשיעור. ההגשה תסומן כממתינה להערכה; היא אינה נבדקת אוטומטית ואינה מעניקה Mastery.
