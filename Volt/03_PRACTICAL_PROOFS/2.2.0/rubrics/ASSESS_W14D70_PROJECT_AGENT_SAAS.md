# הוכחה מעשית · פרויקט: מוצר AI עסקי

צרף תוצר וראיות שאפשר לבדוק. בכל סעיף כתוב הסבר וצרף דוגמה ותוצאה. ההגשה שומרת את העבודה לצורך בדיקה. היא אינה מריצה את הקוד ואינה מחשבת ציון באופן אוטומטי.

## תנאי ההגשה

### 1. BUILD

חבר ממשק משתמש (Frontend), שרת (Backend), אימות זהות (Auth), נתונים, סוכן וכלים. פרוס לסביבת בדיקה (Staging) עם שני לקוחות לדוגמה. הראה תוצר והסבר כיצד בדקת אותו.

**מה לצרף:** צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.

### 2. DIAGNOSE

הרץ עומס קטן, ניסיון גישה זרה וכשל של שירות חיצוני. בדוק את המערכת השלמה. תעד את האבחון ואת התיקון שבדקת.

**מה לצרף:** כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.

### 3. TRANSFER

הגש רשימת בדיקות שחרור (Release Checklist) עם תוצאות שנמדדו ומגבלות שנותרו. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.

**מה לצרף:** צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
