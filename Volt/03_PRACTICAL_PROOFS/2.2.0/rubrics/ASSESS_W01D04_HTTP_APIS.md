# הוכחה מעשית · HTTP וממשקי API

צרף תוצר וראיות שאפשר לבדוק. בכל סעיף כתוב הסבר וצרף דוגמה ותוצאה. ההגשה שומרת את העבודה לצורך בדיקה. היא אינה מריצה את הקוד ואינה מחשבת ציון באופן אוטומטי.

## תנאי ההגשה

### 1. BUILD

קרא שני נתיבי שירות (endpoints) בשרת המעבדה המקומי. הבא את נתוני הלקוח והמוצר לאותו מבנה, עם השדות source ו־data. הגדר מראש זמן המתנה מרבי (timeout). הראה תוצר והסבר כיצד בדקת אותו.

**מה לצרף:** צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.

### 2. DIAGNOSE

בדוק בנפרד 404, 429 ותגובה שאינה JSON. כתוב אם הבעיה נוצרה בתקשורת, בתגובת השירות או בנתונים. תעד את האבחון ואת התיקון שבדקת.

**מה לצרף:** כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.

### 3. TRANSFER

הוסף נתיב שירות (endpoint) חדש והסבר את הבקשה ואת התגובה בלי להסתמך על SDK. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.

**מה לצרף:** צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
