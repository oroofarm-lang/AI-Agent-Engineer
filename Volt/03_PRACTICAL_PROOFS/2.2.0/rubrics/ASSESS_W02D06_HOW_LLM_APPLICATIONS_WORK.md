# הוכחה מעשית · איך אפליקציות LLM פועלות

צרף תוצר וראיות שאפשר לבדוק. בכל סעיף כתוב הסבר וצרף דוגמה ותוצאה. ההגשה שומרת את העבודה לצורך בדיקה. היא אינה מריצה את הקוד ואינה מחשבת ציון באופן אוטומטי.

## תנאי ההגשה

### 1. BUILD

הרץ את אותה משימת סיכום עם מסמך קצר, מסמך ארוך ומידע חסר. בכל הרצה שמור את הקלט, הפלט, מספר הטוקנים שנצרכו וזמן התגובה. השווה את התשובות למידע שבמסמך. הראה תוצר והסבר כיצד בדקת אותו.

**מה לצרף:** צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.

### 2. DIAGNOSE

הסר מהמסמך עובדה שנחוצה לתשובה. בדוק אם המודל מציין שהמידע חסר. תעד את האבחון ואת התיקון שבדקת.

**מה לצרף:** כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.

### 3. TRANSFER

בדוק אותן שאלות עם שני אורכי הקשר. השווה מה התשובות כוללות ומה הן מפספסות. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.

**מה לצרף:** צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
