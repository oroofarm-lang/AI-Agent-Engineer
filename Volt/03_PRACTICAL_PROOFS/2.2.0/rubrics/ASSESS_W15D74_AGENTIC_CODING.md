# הוכחה מעשית · סוכן כתיבת קוד מבוקר

צרף תוצר וראיות שאפשר לבדוק. בכל סעיף כתוב הסבר וצרף דוגמה ותוצאה. ההגשה שומרת את העבודה לצורך בדיקה. היא אינה מריצה את הקוד ואינה מחשבת ציון באופן אוטומטי.

## תנאי ההגשה

### 1. BUILD

בנה את הסדר Plan → Edit → Test → Inspect → Repair על פרויקט בדיקה קטן: תכנון, עריכה, בדיקה, סקירת התוצאה ותיקון. הראה תוצר והסבר כיצד בדקת אותו.

**מה לצרף:** צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.

### 2. DIAGNOSE

צור תיקון שפותר תקלה אחת אך שובר פעולה אחרת. בדוק מה הבדיקות מזהות. תעד את האבחון ואת התיקון שבדקת.

**מה לצרף:** כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.

### 3. TRANSFER

הרץ בדיקות רגרסיה (Regression), סקור את הבדלי הקוד (diff) והסבר את התיקון. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.

**מה לצרף:** צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
