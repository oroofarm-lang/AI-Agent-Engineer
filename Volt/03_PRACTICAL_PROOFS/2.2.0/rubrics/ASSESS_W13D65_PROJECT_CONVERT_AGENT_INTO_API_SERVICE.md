# הוכחה מעשית · פרויקט: שירות Agent API

צרף תוצר וראיות שאפשר לבדוק. בכל סעיף כתוב הסבר וצרף דוגמה ותוצאה. ההגשה שומרת את העבודה לצורך בדיקה. היא אינה מריצה את הקוד ואינה מחשבת ציון באופן אוטומטי.

## תנאי ההגשה

### 1. BUILD

הפוך סוכן קודם לשירות עם אימות זהות (Auth), שמירת נתונים ומעקב אחרי ריצות. בדוק מסלול מלא (End-to-End), מהבקשה ועד לתוצאה שנשמרה. הראה תוצר והסבר כיצד בדקת אותו.

**מה לצרף:** צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.

### 2. DIAGNOSE

הכשל API חיצוני ושלח שוב את בקשת המשתמש. בדוק מה השירות מחזיר. תעד את האבחון ואת התיקון שבדקת.

**מה לצרף:** כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.

### 3. TRANSFER

הדגם בידוד בין לקוחות, ניסיון חוזר בטוח (retry) והודעת כשל ברורה. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.

**מה לצרף:** צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
