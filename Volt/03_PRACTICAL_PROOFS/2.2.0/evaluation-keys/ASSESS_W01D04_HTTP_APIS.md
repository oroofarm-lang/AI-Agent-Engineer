# תנאי בדיקה: הוכחה מעשית · HTTP וממשקי API

אלה תנאי בדיקה המבוססים על המחוון שפורסם. הם אינם מפתח תשובות מלא, ציונים מחושבים או תוצאות הרצה. במשימות שיש להן כמה פתרונות יש לבחון את הנימוק והראיות ביחס לתנאים.

## 1. BUILD

- [ ] העבודה מתייחסת לדרישה: קרא שני נתיבי שירות (endpoints) בשרת המעבדה המקומי. הבא את נתוני הלקוח והמוצר לאותו מבנה, עם השדות source ו־data. הגדר מראש זמן המתנה מרבי (timeout). הראה תוצר והסבר כיצד בדקת אותו.
- [ ] צורפו ראיות שאפשר לבדוק: צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.
- [ ] הוסבר כיצד הראיות תומכות בטענה ומה עדיין לא נבדק.

מיומנות קשורה: PYTHON

## 2. DIAGNOSE

- [ ] העבודה מתייחסת לדרישה: בדוק בנפרד 404, 429 ותגובה שאינה JSON. כתוב אם הבעיה נוצרה בתקשורת, בתגובת השירות או בנתונים. תעד את האבחון ואת התיקון שבדקת.
- [ ] צורפו ראיות שאפשר לבדוק: כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.
- [ ] הוסבר כיצד הראיות תומכות בטענה ומה עדיין לא נבדק.

מיומנות קשורה: HTTP_APIS

## 3. TRANSFER

- [ ] העבודה מתייחסת לדרישה: הוסף נתיב שירות (endpoint) חדש והסבר את הבקשה ואת התגובה בלי להסתמך על SDK. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.
- [ ] צורפו ראיות שאפשר לבדוק: צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
