# תנאי בדיקה: הוכחה מעשית · פרויקט: מנוע קליטת פניות

אלה תנאי בדיקה המבוססים על המחוון שפורסם. הם אינם מפתח תשובות מלא, ציונים מחושבים או תוצאות הרצה. במשימות שיש להן כמה פתרונות יש לבחון את הנימוק והראיות ביחס לתנאים.

## 1. BUILD

- [ ] העבודה מתייחסת לדרישה: קלוט פניות מטקסט, מקובץ ומטופס ושמור את כולן באותו מבנה Lead. תעד את המקור, הפרטים החסרים ותוצאת הבדיקה. תן לכל פנייה מזהה כדי שתוכל לעקוב אחריה. הראה תוצר והסבר כיצד בדקת אותו.
- [ ] צורפו ראיות שאפשר לבדוק: צרף קלט, פלט, גרסה ופקודת הרצה או מסמך אפיון עם מבחן קבלה.
- [ ] הוסבר כיצד הראיות תומכות בטענה ומה עדיין לא נבדק.

מיומנות קשורה: CONTEXT_ENGINEERING

## 2. DIAGNOSE

- [ ] העבודה מתייחסת לדרישה: הזן אותה פנייה פעמיים, ואז שתי גרסאות עם פרטי קשר שונים. בדוק כיצד המערכת מזהה ומציגה את ההבדלים. תעד את האבחון ואת התיקון שבדקת.
- [ ] צורפו ראיות שאפשר לבדוק: כתוב מה ציפית לקבל. צרף את התוצאה לפני התיקון, את הבדיקה שעזרה למצוא את התקלה ואת התוצאה לאחר התיקון.
- [ ] הוסבר כיצד הראיות תומכות בטענה ומה עדיין לא נבדק.

מיומנות קשורה: GROUNDING

## 3. TRANSFER

- [ ] העבודה מתייחסת לדרישה: הוסף סוג פנייה חדש בלי לשנות את מבנה הנתונים של הפניות הקיימות. הצג פתרון עצמאי וציין מקרה שהפתרון אינו מטפל בו.
- [ ] צורפו ראיות שאפשר לבדוק: צרף תוצר חדש, החלטה מנומקת ומקרה שבו הפתרון אינו מספיק.
- [ ] הוסבר כיצד הראיות תומכות בטענה ומה עדיין לא נבדק.
