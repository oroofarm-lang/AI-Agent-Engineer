# Primary-source discovery — phase 5 architecture

Implemented checkpoint, 2026-10-03: the previous three-feed cache has been extended to a versioned public source/technology registry with eight fixed endpoints: OpenAI Agents Python, LangGraph, MCP TypeScript SDK, n8n, Ollama, OpenAI News RSS, the official OpenAI model catalog and API changelog. This covers framework, automation, model-runtime, model-catalog, news and API-change discovery. It is deliberately a curated source set, not a claim to have researched the entire AI ecosystem.

Snapshot schema 2 separates publisher dates from retrieval time, records the exact official endpoint, discovery-only verification status, bounded item metadata and fingerprints, and maps each source through existing course source IDs to actual lessons, modules and skills. Model identifiers are catalog observations, never guarantees of account access or API compatibility. A first observation is distinct from a changed source. Legacy schema 1 remains readable; newly added feeds are marked not checked until genuinely fetched. A legacy cache cannot suppress the first expanded refresh.

Use fixed HTTPS endpoints, reject redirects, stream with size/time limits, never follow embedded links, reject XML declarations of external entities, and retain at most three items per source. News keeps titles/links/dates; model discovery keeps bounded identifiers and the retrieved document hash; changelog discovery keeps a date and a short excerpt with the official page link. Full external pages are not copied into course material. No user records, API keys or provider generation are involved.

The existing Monday/Wednesday/Friday due slots and approved local scheduler are retained. Requests coalesce by the configured cache path; failed checks are retained for the slot to avoid retry storms. Atomic mode-0600 cache writes preserve actual source failures; no refresh rewrites released lessons or awards mastery. `/updates` and authenticated GET `/api/knowledge` expose actual stored results even when the model is unconfigured. Same-origin POST requires a verified configured operator and an empty strict object; it cannot force a repeat for the current slot. The public Volt graph exports source/technology definitions and mappings, not private cache locations or learner data.

Implementation sequence: validated registry and schema/readers; bounded live refresh and legacy/store tests; updates route/page and Mentor context; public Vault links/scheduler documentation; meaningful unit/isolated browser checks, production build/privacy gate, and a real no-key refresh. The [Curriculum Auditor](CURRICULUM_AUDITOR.md) now adds evidence comparison, dependency analysis, exact-hash human decisions, approved section publication and rollback. Discovery and model feedback cannot authorize either action. New IDs, rubrics or catalog dependencies still require a separately reviewed catalog extension.

The GitHub workflow remains manual and does not deploy its artifact into a running server.

The [model catalog](https://developers.openai.com/api/docs/models), [API changelog](https://developers.openai.com/api/docs/changelog) and [OpenAI News](https://openai.com/news) establish endpoint provenance. GitHub feeds follow the [official release API](https://docs.github.com/en/rest/releases/releases#list-releases). Actual retrieval does not verify the behavior of any announced feature.

## Scheduled cloud discovery — 2026-10-04

The GitHub workflow now schedules discovery on Monday, Wednesday and Friday at 06:17 UTC, with manual dispatch retained. Changes to its workflow, refresh command, readers or source registry also trigger a run on main, so configuration updates receive an actual cloud check. It uses the explicit .data/mentor/knowledge.json artifact path and read-only repository permissions. No model key is needed. The local refresh command now loads project configuration before importing the readers, honoring the same MENTOR_KNOWLEDGE_PATH and release-ledger settings as the server. A regression runs the real CLI in a temporary workspace with synthetic .env.local settings and fixture feeds; it never reads the actual private configuration.

The workflow produces a discovery artifact; it does not install it on the application server. The app continues to refresh its own configured cache on demand once per due slot, while a server scheduler can run npm run mentor:refresh against that same persistent directory. Actual deployment and scheduled server execution remain unverified. The configured cron is not proof that a schedule event ran. GitHub documents possible delayed/dropped scheduled jobs and disables schedules in inactive public repositories after 60 days: [schedule behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). A failed source remains visibly unavailable; neither a cloud artifact nor a refresh grants approval to change released lessons.
