# Reinforcement answers and immutable course updates

The practical-proof wizard's existing question about submission versus mastery now stores real choices per authenticated user and lesson. Its previously shipped copy lives in the versioned public system-question catalog. This does not publish the separate 139-question teaching draft or change released lessons.

The implementation uses the existing Next.js Node routes, Better Auth identity, Zod validation, SQLite transactions and foundation gate. New files: `content/quizzes/system/1.0.0.json`, `src/lib/quizzes/catalog.ts`, `src/lib/db/quizzes.ts`, additive migration 0012, `/api/quizzes` and `src/components/assessment/reinforcement-quiz.tsx`. The assessment form composes the new component. The server is authoritative for grading this defined answer, timestamps, frozen copy and ownership; a correct reinforcement answer never writes progress, XP, mastery or human-review records.

Catalog contract: stable question ID, semantic version, prompt, distinct stable options, correct option and actual explanatory feedback. Submission contract: UUID request ID, stable lesson ID, question hash, exact current curriculum version and defined option ID. Persist a composite owner/request key, frozen question, content fingerprint, selected option, deterministic correctness and timestamp. Same owned token/payload is idempotent; a changed payload conflicts. Old attempts remain readable as original snapshots. A bound of 500 actual attempts per UTC day prevents write floods without restricting ordinary course practice. Reads and writes enforce published lesson membership and current foundation access.

Learner copy states that answers are saved, distinguishes practice from assessment and exposes real load/save failures with a retry that retains the same UUID. Export/deletion include all attempts. Mentor receives only a bounded relevant summary of actual attempts, never synthetic quiz results. The Orchestrator uses those facts through its existing progress tool. Apply the additive migration only after a private online backup; preserve all old data and never print user rows or credentials. Meaningful tests cover ownership, payload conflict, immutable snapshots, foundation rules, rate limits, rollback, export/deletion and a reload/login browser journey.

For Curriculum Auditor work, keep DISCOVER → VERIFY → COMPARE → CLASSIFY → DEPENDENCY ANALYSIS → PROPOSE → HUMAN APPROVAL → APPLY → VALIDATE → VERSION. Current discovery is implemented; next stages require bounded primary-source passages, exact patch/base hashes, dependency impact, a genuine review screen and approved immutable release activation/rollback. Technical retrieval is not automatic verification; no foundation rewrite from marketing. Released IDs, prior assessments/mastery, notebooks and conversations remain preserved. The question draft stays inactive until its exact reviewed version receives human pedagogic approval.
