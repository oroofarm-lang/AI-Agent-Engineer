# חיבור Gmail לשליחת מיילים מהקורס

החיבור משמש לשליחת אימות חשבון וקישורים לאיפוס סיסמה. הוא אינו קורא את
תיבת הדואר שלך ואינו רושם משתמשים לרשימת תפוצה.

אם Google מציגה ש״סיסמאות לאפליקציות״ אינן זמינות למרות שאימות דו־שלבי פעיל,
אפשר להשתמש ב[מדריך OAuth לשליחה בלבד](GMAIL_OAUTH_HE.md). ההודעה לבדה אינה מוכיחה מה סיבת החסימה.

1. בחשבון Google שממנו תרצה לשלוח, הפעל אימות דו־שלבי.
2. פתח https://myaccount.google.com/apppasswords וצור סיסמת אפליקציה בשם
   `Agent Engineer`. אל תשתמש בסיסמת החשבון הרגילה ואל תשלח את הקוד בצ׳אט.
3. בטרמינל של הפרויקט הרץ `npm run mail:setup:gmail`. הזן את כתובת השליחה
   ואת סיסמת האפליקציה. הסיסמה אינה מוצגת בהקלדה או ביומן הפקודה.
4. הרץ `npm run mail:check`. הצלחה מאשרת חיבור ואימות מול SMTP; הבדיקה
   אינה שולחת הודעה ואינה מוכיחה הגעה לתיבת הדואר.
5. הפעל מחדש את שרת האפליקציה. לאחר מכן בדוק בפועל את ״שכחתי סיסמה״
   בחשבון קיים ואת הגעת ההודעה, כולל תיקיית הספאם. קישור האיפוס הוא לשימוש
   חד־פעמי; שינוי הסיסמה מבטל את החיבורים הקודמים לחשבון.

הפקודה שומרת רק את שדות המייל ב־`.env.local`, ומשאירה את יתר ההגדרות.
הקובץ מוחרג מ־Git ונשמר בהרשאות פרטיות. היא מגדירה `smtp.gmail.com`, פורט
465 עם TLS, כתובת משתמש וכתובת שולח זהות, ומנקה SMTP_URL קודם שמתחרה בהן.
לאחר מעבר לאחסון ציבורי יש להזין אותם שדות במנהל הסודות של השרת ולהגדיר
`BETTER_AUTH_URL` לכתובת HTTPS הציבורית; הגדרה מקומית אינה פריסה ציבורית.

אם ״סיסמאות לאפליקציות״ אינו מופיע, Google מציינת בין הסיבות האפשריות
הגנות מתקדמות, אימות המבוסס רק על מפתחות אבטחה או חשבון ארגוני. שינוי
סיסמת Google מבטל סיסמאות אפליקציה קיימות.
מקור: [הנחיות Google לסיסמאות אפליקציה](https://support.google.com/accounts/answer/185833),
נבדק ב־2026-10-04. הגדרות TLS ופורט:
[תיעוד SMTP של Nodemailer](https://nodemailer.com/smtp).

מצב האימות כרגע: לא הוזנה סיסמת אפליקציה במסגרת העבודה הזאת ולא נשלח
מייל אמיתי. בדיקות הקוד משתמשות בפרטים סינתטיים ובשירות מייל מדומה.
