# פריסת הקורס על שרת עם אחסון מתמשך

## ההחלטה

המסד הקיים הוא SQLite. לכן חבילת הפריסה מפעילה מופע Node אחד על שרת Linux עם Docker Compose ואחסון מתמשך. אין לפרוס אותה על אחסון זמני או להגדיל למספר מופעים בלי תכנון מעבר למסד משותף. חבילה זו טרם הותקנה על שרת ציבורי.

## מה נשמר

- learning-data: המסד, גיבויים, גרסאות הקורס והשאלות שאושרו ומטמון מקורות הידע.
- public-vault: ייצוא Volt, ההיסטוריה שלו וההגנה על רשומות שנערכו ידנית.
- next-cache: מטמון זמני של Next.js, שאינו תחליף למסד.
- caddy-data ו־caddy-config: תעודות HTTPS והמצב של שרת הכניסה.

קובצי ההגשות נשמרים במסד הפרטי. Dockerfile אינו מעתיק קובצי סביבה, מסדים, תיקיית .data או Volt אישי לתמונת האפליקציה. ערכי הסביבה נמסרים רק בהפעלה. לפני עדכון מסד קיים נעשה גיבוי עקבי באמצעות SQLite, ולא העתקה של קובץ פעיל.

## מה צריך לפני הפעלה

שרת Linux עם Docker Compose, דומיין שמצביע אליו ופורטים 80 ו־443 זמינים. הכן כתובת Gmail לשליחה שכבר אושרה באמצעות OAuth או SMTP, מפתח אימות קבוע, פרטי מפעיל וכתובת קשר. חיבור AI הוא נפרד: נדרשים מפתח ומודל זמינים אם רוצים להפעיל את המנטור. בלי חיבור כזה הקורס אינו ממציא תשובות AI.

בתיקיית הפרויקט בשרת צור .env.production בהרשאות 600. העתק את שמות ההגדרות מ־.env.example ומלא ערכים אמיתיים. בנוסף הגדר APP_DOMAIN לשם הדומיין בלבד ו־ACME_EMAIL לכתובת לקבלת התראות תעודה. BETTER_AUTH_URL חייב להיות כתובת HTTPS של אותו דומיין. אין לשלוח את הקובץ בצ׳אט או להוסיף אותו ל־Git. אין להריץ docker compose config ללא --quiet ביומן משותף: הפלט המלא יכול לכלול סודות.

הרץ בדיקת תצורה:

```
docker compose --env-file .env.production config --quiet
```

לאחר שהבדיקה מצליחה:

```
docker compose --env-file .env.production up --build -d
```

האתר אינו אמור להיחשף דרך פורט 3000. Caddy הוא שרת הכניסה היחיד ומעביר כתובת לקוח אמיתית בכותרת X-Real-IP, במקום כותרת שהמבקר סיפק. התצורה מיועדת לחיבור ישיר של האינטרנט ל־Caddy; הוספת Cloudflare או שרת כניסה נוסף מחייבת בדיקת כתובות מהימנות מחדש.

Caddy מגביל את גוף הבקשה ל־12MB, בהתאם למגבלת Server Actions. הפעלת HTTPS בפועל עדיין דורשת דומיין, DNS, פורטים ותהליך הנפקה תקין. תצורת שרת כניסה אינה אישור שהאתר עלה או שהמייל הגיע.

## הפעלה מחדש ועדכון

בהפעלה על מסד חדש מתבצעת יצירת הטבלאות. במסד קיים נשמר קודם גיבוי פרטי, ורק אז מופעלות המיגרציות שנוספו. כשל גיבוי או מיגרציה עוצר את ההפעלה. שינוי ידני ברשומת Volt אינו נמחק: כשל בהקרנה מוצג ביומן וניתן לטיפול דרך ממשק המנהל, בעוד הלמידה ממשיכה.

בדיקת המוכנות קוראת רק את רשומות המיגרציות ואת ההגדרות הציבוריות שלהן, ובודקת שעמוד הכניסה מחזיר 200. היא אינה יוצרת מסד חסר, אינה מחזירה פרטי לומדים ואינה מוכיחה תקינות של מייל, ספק AI או כל פעולות הקורס. זמן העצירה מאפשר לשרת לסיים בקשות פעילות.

לפני שדרוג: שמור גיבוי חיצוני של המסד ושל ספריות הגרסאות. גיבוי באותו שרת אינו מגן מפני אובדן השרת. אין להשתמש ב־docker compose down -v במערכת חיה: הפעולה מוחקת את כרכי האחסון. מדיניות מחיקה וגיבוי חייבת להתאים להתחייבויות כלפי המשתמשים. אין שחזור אוטומטי של חשבונות שנמחקו.

## תחזוקה וחיבור העדכונים לשרת

על השרת הפעיל תזמן npm run mentor:refresh שלוש פעמים בשבוע ואת npm run db:cleanup פעם ביום. דרך אותה חבילת Compose אפשר להריץ אותן כך, עם הנתיבים המתמשכים שהוגדרו לשירות:

```
docker compose --env-file .env.production run --rm --no-deps --entrypoint npm app run mentor:refresh
```

```
docker compose --env-file .env.production run --rm --no-deps --entrypoint npm app run db:cleanup
```

בקבצי deploy/systemd הוכנו שני זוגות service/timer להפעלה דרך systemd על Linux: רענון בימי שני, רביעי ושישי ב־06:17 UTC, וניקוי רשומות אימות שפג תוקפן בכל יום ב־06:35 UTC. אלו שעות UTC קבועות; השעה המקומית בישראל משתנה עם שעון הקיץ. שתי הפעולות משתמשות באותה תצורת Compose ובאותם כרכי אחסון. אין צורך בהעתקת מפתחות לקובצי התזמון.

ברירת המחדל היא התקנה בתיקייה /opt/AI-Agent-Engineer ו־Docker ב־/usr/bin/docker. אם התקנת השרת שונה, יש לעדכן WorkingDirectory ו־ExecStart בשני קובצי השירות לפני ההתקנה. אין להתקין אותם במחשב ה־Mac: הם מיועדים לשרת Linux עם systemd.

אחרי שהשרת עלה ו־.env.production הוגדר, התקן על השרת בלבד:

```
sudo install -m 644 deploy/systemd/ai-course-* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ai-course-mentor-refresh.timer ai-course-auth-cleanup.timer
```

אמת את זמני ההפעלה:

```
systemctl list-timers ai-course-mentor-refresh.timer ai-course-auth-cleanup.timer
```

בצע בדיקת רענון אמיתית בשרת:

```
sudo systemctl start ai-course-mentor-refresh.service
systemctl status ai-course-mentor-refresh.service
```

בדוק שהשירות הסתיים עם תוצאה תקינה ושעמוד עדכוני הידע מציג רענון חדש. היומן אמור להכיל סטטוס מקורות ציבוריים בלבד; אין להעתיק סודות או נתוני תלמידים לדוח. Persistent=true מאפשר הפעלה אחת להשלמת מועד שהוחמץ כשהתזמון הופעל בעבר והשרת היה כבוי. systemd אינו מפעיל במקביל מופע נוסף של אותו שירות שכבר רץ. כשל אינו מפעיל לולאת ניסיונות חוזרים: הוא דורש בדיקת מפעיל או המתנה למועד הבא.

להסרה עתידית של התזמון בלבד, בלי מחיקת נתונים:

```
sudo systemctl disable --now ai-course-mentor-refresh.timer ai-course-auth-cleanup.timer
```

תזמון השרת יותקן וייבדק לאחר שיש שרת אמיתי. בדיקת התחביר ב־CI אינה הוכחה שטיימר פעל בשרת הציבורי. ה־workflow ב־GitHub מפיק קובץ גילוי ציבורי; הוא אינו מתקין אותו אוטומטית על שרת זה. הפקודה בשרת מרעננת ישירות את המטמון שבו המנטור משתמש. רענון אינו משנה שיעור משוחרר ללא אישור אנושי.

## קבלה לפני הזמנת תלמידים

בדוק דרך הדומיין האמיתי הרשמה, הגעת אימות, כניסה, עריכת טבלה, העלאת קובץ, הגשה, התקדמות אחרי כניסה מחדש ואיפוס סיסמה. חזור על התהליך בחשבון שני וודא הפרדת מידע. בדוק שחזור מגיבוי מבודד והפעלה מחדש ללא אובדן עבודה. הפעל את המנטור רק אחרי בקשת בדיקה אמיתית עם ספק ה־AI. הוסף ניטור זמינות, הגבלות תעבורה ברמת האחסון ומדיניות גיבוי לפני פתיחה לציבור.

## בדיקות החבילה

GitHub Actions בונה תמונה ללא סודות, מאמת את תצורת Caddy, מפעיל אותה עם פרטים סינתטיים ובודק מוכנות, שמירת מסד לאחר החלפת המכולה וגיבוי לפני מיגרציה. היא גם משנה רשומת בדיקה, משחזרת את הגיבוי בכרך הבדיקה ומוודאת הפעלה מחדש עם הערך המקורי. תצורת Compose נבדקת עם הגדרות סינתטיות וללא הדפסתן. כרכי הבדיקה נוצרים ונמחקים בנפרד. SMTP בבדיקת המכולה אינו שירות פעיל ואין שליחת מייל. בדיקת המכולה אינה פריסה ציבורית או הסמכת נגישות.
