# Incremental learning system — implementation contract

This slice completes the currently missing project/Boss workspace and human assessment path before the new lesson-navigation and pedagogy changes. It does not complete the Auditor or public deployment.

Projects and the four Boss challenges are identified by the existing source-defined PROJECT/BOSS lesson IDs, not invented projects. Their brief, requirements, failure exercise, extension and acceptance criteria are the released instructional sections and rubric. Project workspaces store the learner's architecture, test log and reflection with optimistic revisions; code runs only in the learner's chosen environment. Boss attempts are explicit, user-owned, versioned and linked to an exact evidence submission; at most one active attempt per challenge. No time-based score or automatic pass is created.

A verified configured operator can review a submitted rubric, recording 0–3 and substantive feedback for every criterion. A passing attempt requires all criteria at least 2. The reviewer cannot approve their own submission. Reviews are append-only, single-review-per-attempt and idempotent; a rejected attempt is improved by submitting a new attempt. Highest demonstrated skill levels and mastered lesson states are preserved when later attempts fail or the curriculum changes. Rubric snapshots, reviewer identity, curriculum version and feedback form the audit trail. This is a human judgment, not evidence that the platform executed the learner's code. Private evidence is shown to authorized reviewers, disclosed in privacy copy; ordinary account-directory views expose only registration and counts.
